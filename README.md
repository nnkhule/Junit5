## 7. Mutation Testing

Mutation testing хийхийн тулд `GradeCalculator.java` файлын дараах нөхцөлийг түр өөрчилсөн:

```java
if (score >= 90)
```

гэдгийг:

```java
if (score > 90)
```

болгож туршсан.

Энэ өөрчлөлтийн үед яг 90 оноо `A` биш `B` болж буруу үр дүн гарсан. Үүнийг `ninetyIsExactlyA` болон parameterized test-ийн 90 онооны test case илрүүлсэн.

Mutation test-ийн үр дүн:

```text
Tests run: 28, Failures: 2, Errors: 0, Skipped: 0
BUILD FAILURE
```

Энэ нь тестүүд уг кодын өөрчлөлтийг илрүүлж чадсаныг харуулж байна.

Mutation test-ийн дараа кодыг буцаан:

```java
if (score >= 90)
```

болгож сэргээсэн.

Дараа нь бүх тестийг дахин ажиллуулахад:

```text
Tests run: 28, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

үр дүн гарсан.

Mutation testing-ийн үр дүнг:

```text
results/mvn-test-mutant.txt
```

файлд хадгалсан.

## 8. Хамгийн сонирхолтой тест ба илрүүлсэн алдаа

Энэ лабораторийн хамгийн сонирхолтой хэсэг нь 90 онооны boundary test байсан. Учир нь `>= 90` болон `> 90` гэсэн хоёр нөхцөл харахад маш төстэй боловч 90 оноо дээр өөр өөр үр дүн өгдөг. `90` оноо нь A үнэлгээний яг доод хязгаар тул boundary test нь энэ жижиг кодын өөрчлөлтийг шууд илрүүлсэн. Иймээс зөвхөн энгийн утгуудыг шалгахаас гадна хязгаарын утгуудыг заавал тестлэх нь чухал гэдгийг энэ туршилт харуулсан.


## 9. Дүгнэлт

Энэ лабораторийн ажлаар Maven төсөлд JUnit 5 тохируулж, `GradeCalculator` классын үндсэн функцүүдэд unit test боловсруулсан. Нийт 16 test method болон 28 test case ажиллуулж, энгийн утга, boundary утга болон буруу оролтуудыг шалгасан. Parameterized test ашигласнаар олон төрлийн оролтыг нэг тестийн бүтэцтэйгээр шалгах боломжтой болсон. Mutation testing хийх үед `>= 90` нөхцөлийг `> 90` болгон өөрчлөхөд тестүүд алдааг илрүүлж, 2 test failure гаргасан. Mutation-ийн дараа кодыг сэргээж дахин ажиллуулахад бүх 28 test case амжилттай ажиллаж `BUILD SUCCESS` болсон. Ингэснээр JUnit 5-ийн unit testing, boundary testing, parameterized testing болон mutation testing-ийн үндсэн ойлголтуудыг практик байдлаар хэрэгжүүлсэн.

Мутаци хийсэн үед `ninetyIsExactlyA` тест болон parameterized тестийн `90 → A` case нийт 2 тест унасан бөгөөд бусад 26 тест өнгөрсөн. Энэ нь яг тэр нэг нөхцөлийг л хязгаарын тест шалгаж байгааг, 95 эсвэл 100 гэх мэт энгийн утгууд мутацийг илрүүлж чадахгүй байсныг харуулсан. Хэрэв би зөвхөн 95 оноог тестэлсэн бол `>= 90` ба `> 90` хоёрын ялгааг хэзээ ч олж харахгүй байсан. Иймээс цаашид нөхцөл бүхий кодыг тестлэхдээ хязгаарын утга болон түүний хоёр талын утгыг (90, 89.99) заавал шалгах хэрэгтэй гэдгийг энэ лабораториос сурсан.
